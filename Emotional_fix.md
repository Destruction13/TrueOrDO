# Emotional (Эмоциональный интеллект) — список правок

Дата: 2026-02-03

## Контекст (как сейчас работает)
1. После выкладки карт на стол они **открываются спустя 5 секунд**.
2. Затем **каждые 0.5 секунды** карты «переворачиваются»/раскрываются другой стороной.
3. После этого происходит **обновление страницы**, и уже на новой странице появляется **таймер**.

## Что нужно изменить

### 1) Убрать обновление страницы; таймер показывать через рендер (без reload)
- Требование: **никакого обновления страницы** после этапа с раскрытием карт.
- Вместо этого: UI должен **перерендериться** и **таймер должен появиться**.
- Важно: таймер должен появляться **по центру экрана**.
- Важно: в этом моменте таймер должен быть **полностью круглым** (полное кольцо), **а не полукругом**.
  - Уточнение: изменение «полностью круглый» нужно **ТОЛЬКО для этого конкретного момента** (когда таймер появляется по центру после раскрытия карт).
- Дополнительно: таймер должен появляться **не в зоне/месте блока с фразой**, а именно отдельным центральным элементом.

### 2) Рука с картами должна отображаться только в начале хода (когда идёт объяснение)
- Требование: **на всех этапах, кроме начала хода**, где существует блок с фразой, **рука с картами должна отсутствовать**.
- Иными словами: показываем руку (hand/cards) **только когда идёт ход и объяснение**.
- После этого этапа рука не нужна: её функционал бесполезен и она визуально отвлекает.

### 3) Не запускать таймер/голосование, если на столе только карта ведущего
- Требование: если **никто не выложил карточку**, и на столе присутствует **только карта ведущего**, то:
  - **не нужно запускать таймер**,
  - **не нужно переключать UI в фазу таймера** (не делать соответствующий рендер),
  - так как **в этом голосовании нет смысла**.
- Логическое правило: фаза голосования/таймера стартует только если на столе есть **минимум 2 карты** (карта ведущего + хотя бы одна карточка игрока).

### 4) Убрать тексты на экране во время голосования
- Сейчас во время голосования показываются тексты:
  - **"Выберите эмоцию, которая была у ведущего"**
  - **"Ваш голос принят"**
- Нужно: **убрать оба текста** (ничего из этого не отображать в UI на этапе голосования).

### 5) После показа карточки(ек)-победителя очистить стол и дать хосту кнопку "Следующий раунд"
- Требование: после того, как показана карточка-победитель, за которую проголосовало большинство игроков
  - (или несколько карточек, если результат голосования привёл к одинаковому количеству голосов),
  - победившие карточки нужно **показать**.
- Затем стол очищается **не сразу**, а **через 5 секунд после показа** карточки(ек)-победителя:
  - очистка должна быть **синхронной для всей комнаты**,
  - и выполняться **без обновления страницы** (через рендер/состояние, а не reload).
- После завершения голосования у **хоста** появляется кнопка **"Следующий раунд"**:
  - Кнопка появляется **ТОЛЬКО после завершения голосования**.
  - Расположение: **по центру овального стола**.
  - Нажатие на кнопку запускает **новый раунд**.

### 6) Исправить перекрытие текста соседней карточкой в руке (mobile + desktop)
- Проблема: в руке (колода на экране) **отступ между соседними карточками слишком маленький**.
  - Из-за этого длинные слова/строки на текущей карточке визуально **заходят под/за границу следующей карточки**.
  - На мобильных экранах ощущается сильнее: при малой ширине экрана шрифт уменьшается, но **перенос строк отрабатывает плохо**, и текст продолжает вылезать.
- Нужно:
  - **увеличить расстояние (gap/margin) между карточками** в руке, чтобы текст не мог оказаться под соседней карточкой,
  - корректно настроить **перенос строк** (wrap) на 2+ строк,
  - гарантировать, что слова **никогда** не пересекают визуальную границу следующей карточки.
- Дополнение: в состоянии «малая ширина экрана» перенос должен работать лучше, чем простое уменьшение шрифта.
- Ожидаемое поведение:
  - для любых слов/фраз текст укладывается внутри карточки (в пределах padding) и переносится по строкам,
  - на mobile и desktop нет налезания текста на соседнюю карточку.
- Вероятные места правок (ориентир):
  - CSS/верстка компонентов руки/карточек в `client/src/components/emotional/*` (например, контейнер со списком карточек и сама карточка: padding, line-height, overflow-wrap/word-break, max-width).

### 7) Починить кнопку "Настройки" (шестерёнка) сверху справа
- Проблема: кнопка "Настройки" вверху справа выглядит как **сломанная шестерёнка** (иконка отображается некорректно).
- Нужно: привести иконку/кнопку к нормальному виду (корректный glyph, размер, выравнивание, без обрезания/артефактов).
- Ожидаемое: на mobile и desktop иконка выглядит аккуратно и читаемо.

### 8) Добавить на desktop 2 боковых блока (Игроки/очки + Отчёт раунда) и адаптацию для mobile
#### 8.1 Desktop (>= 1200px)
1) **Слева от овального стола**
- Разместить плашки игроков (без внешней обёртки-карточки блока):
  - каждая строка — отдельная плашка,
  - слева никнейм, **справа очки**.
- Дизайн: единый стиль с остальным UI (цвета/шрифты/скругления/подсветки как в игре).

2) **Справа от овального стола** — блок **"Отчёт раунда"**
- Внутри: список **катов** (раскрывающиеся секции).
- Поведение:
  - при открытии ката он **расширяется**, а остальные каты **сдвигаются вниз**,
  - при закрытии позиции восстанавливаются.
- Размеры:
  - кат должен быть **ограничен по высоте**,
  - при превышении высоты внутри ката появляется **внутренний скролл** (scroll внутри ката).
- Контент ката:
  - строка: **"<Никнейм ведущего> показывал эмоцию: <X>"**
  - ниже: **"Игроки выбрали <X>:"** и список никнеймов игроков, которые указали на эмоцию X.

#### 8.2 Mobile (< 1200px)
- Добавить эти 2 блока **снизу**.
- Нужен отдельный контейнер, который вмещает оба блока вертикально:
  - сверху — блок игроков/очков (который на desktop слева),
  - ниже — блок отчёта раунда (который на desktop справа).
- Отличие от desktop:
  - блок отчётов/каты на mobile должны **толкать контент вниз**, но **без внутреннего скролла**,
  - при раскрытии катов блок растёт **по высоте вниз без ограничений** (условно «до бесконечности»), т.к. на mobile предполагается прокрутка страницы, а не мелкий scroll внутри ката.

### 9) Поведение карточек: hover/click анимации + mobile drag вверх
- Сейчас: при наведении карточки слегка увеличиваются; при нажатии карточка "вылезает" поверх; анимация резкая.
- Нужно (desktop):
  - **Hover (наведение)**: должен давать **тот же эффект**, что сейчас даёт нажатие — карточка **поднимается/вылезает поверх** (выходит на передний план по z-index).
  - **Click (нажатие)**: карточка так же **вылезает поверх** + появляется **свечение бордера** (и остальные текущие эффекты выбора сохраняются).
  - Анимации (hover/click/поднятие/возврат): сделать **максимально плавными и приятными** (убрать резкость; увеличить duration; добавить easing).

- Нужно (реальные мобильные устройства, не просто <1200px):
  - 1-е нажатие по карточке: **только поднимает/выводит наверх** (аналог hover на desktop), чтобы снизить шанс случайного выбора.
  - Далее предпочтительно: если пользователь **тянет карточку вверх**, то карточка **ставится на стол** (drag вверх = подтверждение).
  - Если drag реализовать невозможно/слишком сложно:
    - тогда нажатие по карточке **сразу выбирает** (ставит), но нужно понимать, что это убирает защиту от случайного тапа.

- Примечания по реализации:
  - Для различения "реально mobile" ориентироваться на touch/pointer (`pointer: coarse`, наличие `ontouchstart`, Pointer Events), а не только на ширину экрана.
  - Для плавности: использовать CSS transitions/Framer Motion (в проекте уже используется Framer Motion) для transform/z-index/box-shadow.
  - Для drag: рассмотреть `framer-motion` drag (axis=y) с порогом (threshold) по смещению вверх.

### 10) Улучшить анимацию переворота карточки на столе (визуальный flip карточки)
- Сейчас переворот ощущается так, будто "переворачивается только текст".
- Нужно:
  - сделать визуальный **переворот самой карточки** (flip по 3D/ось Y или X с backface),
  - анимацию сделать **медленнее** и более читаемой.
- Ожидаемое: при раскрытии на столе видно, что именно карточка перевернулась, а не просто сменился/перевернулся текст.

### 11) Гарантировать уникальность эмоций на столе + визуальная колода на desktop
#### 11.1 Уникальность карточек (ГЛОБАЛЬНО во всей игре)
- Проблема: сейчас карточки эмоций **иногда повторяются** (одна и та же эмоция может оказаться у нескольких игроков).
- Требование: **уникальность должна быть глобальной** — не должно быть ситуации, когда **одна и та же эмоция** находится у нескольких игроков одновременно (в руках/на столе), и в целом не должна повторяться повторно по ходу игры.
- Допущение: **карточки могут закончиться** — это нормально.
- Следствие для логики раздачи/руки:
  - фактически нужно перейти на модель колоды без копий (или с механикой строгого "без повторов"), т.е. одна эмоция = одна карточка.
  - `dealHands()`/`drawFromDeck()` должны выдавать карточки так, чтобы одна и та же эмоция не могла попасть в игру второй раз.

#### 11.2 Визуальная колода (desktop)
- Требование: добавить **визуальную колоду** на desktop-версии **слева**, под информацией о счёте игроков (под блоком плашек игроков/очков из п.8.1).
- Поведение:
  - по мере уменьшения количества карточек, оставшихся в колоде, визуально **уменьшать колоду** (меньше "слоёв"/высоты стопки).
- Внешний вид:
  - ориентироваться на вид **сложенной карточной колоды** (стопка карт), например как в игре "Дурак": несколько карт, слегка смещённых, создающих эффект толщины.

### 12) Плавный рендер карточек + убрать выложенную карточку из руки игрока
- Требование: если игрок выложил карточку на стол, она должна **исчезнуть из руки** у этого игрока (визуально), чтобы было понятно, что карта уже сыграна.
- Требование: рендер/появление карточек (на столе и/или в руке) сделать **мягким и плавным**:
  - убрать резкие переходы,
  - убрать "мигание" при обновлении состояния/перерисовке.
- Примечания:
  - использовать плавные transitions/Framer Motion (opacity/transform/layout) и избегать полного пересоздания DOM-узлов без ключей.

### 13) Завершение игры: заменить текст на модальное окно с лидербордом

### 14) Экран ожидания старта игры: заменить текст и добавить градиентную анимацию
- Сейчас у игроков показывается текст: **"Ждём, когда хост начнёт игру"**.

## Ожидаемый UX/логика состояний (в терминах UI)
- Состояние «карты на столе, ждём 5 секунд, затем flip каждые 0.5 сек» остаётся, но переход к следующему шагу:
  - делается **без перезагрузки страницы**,
  - через **локальное состояние React** и/или **Socket.IO state sync**.
- После завершения флипа:
  - появляется **центральный круглый таймер**,
  - при этом не должно быть скачка/перезапуска страницы.

- `client/src/components/alias/TextShimmer.jsx`
  - готовый эффект shimmer/перелива текста, подходит как ориентир/переиспользование для «Ожидание начала игры».

### Ключевые серверные файлы (по факту текущей реализации)
- `server/src/game/emotional.js`
  - хранит room state и фазы.
  - важно:
    - раздача/добор руки: `dealHands()` -> `drawFromDeck()`
    - сбор стола и удаление выбранной карты из руки: `advanceToVote()` (там `hand.splice`)
    - результаты/победители: `finalizeRound()` (сейчас оставляет на столе только winnerSlots)

- `server/src/index.js`
  - Socket.IO события Emotional: `emotional:room:*`, `emotional:game:start`, `emotional:turn:*`, `emotional:vote:*`, `emotional:round:next`, `emotional:game:new`.
  - автоматические переходы фаз/раскрытия карт/таймера: `startEmotionalTimer(roomCode)`
    - reveal логика: 5 секунд ожидания, затем каждые 0.5 сек раскрытие слота слева направо
    - переход `reveal -> vote` делается через `advanceEmotionalRevealToVote()`

### Важное наблюдение по вашему требованию «страница обновляется»
- В текущем клиентском коде Emotional **нет** `location.reload()`/`window.location.reload()`.
- Переходы, которые выглядят как «обновление страницы», происходят из-за:
  - смены `room.phase` (условный рендер разных блоков в `EmotionalRoomScreen.jsx`),
  - и частого `emotional:state:sync` во время reveal.
- Следовательно, правка должна быть в сторону **уменьшения резких mount/unmount** и перенос элементов внутрь `EmotionalOvalTable` (чтобы сохранялась одна и та же «сцена»), а не борьба с реальным reload.

Сервер (если таймер/фазы завязаны на серверные события):
- `server/src/game/emotional.js`
- `server/src/index.js` (Socket.IO handlers / state sync)

## Критерии готовности
- После раскрытия/переворота карт **страница не перезагружается** (нет `location.reload`, навигации, unmount/remount страницы и т.п.).
- Таймер появляется **по центру**, и в этот момент он **полностью круглый**.
- **Рука с картами** отображается **только** в фазе «ход/объяснение» и скрыта во всех остальных фазах.

## Примечания по реализации (под стиль проекта)
- Фазы сейчас уже выражены явно через `room.phase`: `lobby | submit | reveal | vote | results | ended`.
  - Большинство UX-правок лучше делать не созданием новых фаз, а **переразметкой внутри существующих фаз** (или очень аккуратно добавлять новые флаги в room state), чтобы не ломать таймер и автопереходы.
- Все пользовательские тексты — на русском.

## Предложенный подход внедрения (конкретные примеры)

### A) «Страница обновляется» / таймер должен появляться по центру без визуального "перезапуска"
**Где сейчас:**
- `server/src/index.js` -> `startEmotionalTimer()` переключает `reveal -> vote` через `advanceEmotionalRevealToVote()`.
- `client/src/components/emotional/EmotionalRoomScreen.jsx` при смене `room.phase` размонтирует один блок (`phase-reveal`) и монтирует другой (`phase-vote`). Из-за `AnimatePresence` и разных ключей `key="phase-*"` это ощущается как обновление.

**Что лучше сделать:**
- Свести `reveal` и `vote` к одной «сцене стола»:
  - либо: оставить общий контейнер `EmotionalOvalTable` смонтированным всегда, а менять только его props (в т.ч. `centerTimer`, `onSlotClick`, `showVotes`, `centerWord`),
  - либо: уменьшить различия в layout между `phase-reveal` и `phase-vote` (убрать заголовки/тексты сверху, чтобы центр сцены не прыгал).

**Таймер круглый только в одном моменте:**
- Использовать `RadialCountdown` с `variant="full"` только при первом появлении таймера по центру после reveal.
- Технически это проще всего сделать на клиенте, введя вычисляемый флаг вида `showCenterVoteTimerAsFullCircle`, основанный на `room.phase === "vote"` и «первой секунде после перехода».
  - Альтернатива надёжнее (сервер): добавить в room state метку времени `voteStartedAt` и на клиенте показывать полный круг при `nowMs - voteStartedAt < N`.

### B) Не запускать голосование, если на столе только карта ведущего
**Где лучше решать:** сервер.
- `server/src/game/emotional.js` -> `advanceToVote(room)` формирует `room.table` из сабмитов + добавляет карту ведущего.
- Добавить проверку: если после формирования стола `room.table.length < 2`, то **не переходить в reveal/vote**.
  - Возможные варианты поведения:
    1) сразу завершать раунд без голосования и переходить в `results` (с `roundResult`),
    2) или сразу разрешать хосту `nextRound`.

### C) Убрать руку с картами везде, кроме фазы submit
**Где:** `EmotionalRoomScreen.jsx`.
- Сейчас рука передаётся даже в `reveal/vote/results` через `myHand={gameState?.my?.hand || []}`.
- Сделать так, чтобы `myHand` передавался только при `room.phase === "submit"`.

### D) Убрать тексты в голосовании
**Где:** `EmotionalRoomScreen.jsx`.
- В `phase-vote` удалить блок `emotional-room__game-hint` (строка ~278) полностью.

### E) После показа победителя: задержка 5 сек, очистка стола, кнопка хоста по центру стола
- Уточнение: кнопка **"Следующий раунд"** появляется **ТОЛЬКО после очистки стола** (а не сразу после завершения голосования).
**Где сейчас:**
- Сервер: `finalizeRound(room)` переводит в `phase="results"` и оставляет на столе только победившие карты.
- Клиент: в `phase-results` кнопка `Следующий раунд` находится снизу в `emotional-room__hand-actions`.

**Как лучше:**
- Ввести на сервере дополнительную метку, например `resultsShownAt`.
- На клиенте:
  - показывать победившие карты в `results`.
  - через 5 секунд после `resultsShownAt` скрывать стол (или сервер очищает `room.table = []` + sync).
  - кнопку `Следующий раунд` (только хост) рендерить как `centerAction` внутри `EmotionalOvalTable` и показывать только после очистки.

### F) Уникальность карточек на столе
**Где решать:** сервер.
- Сейчас на сервере есть `EMOTION_COPIES = 6`, и `dealHands()` берёт из колоды, поэтому дубликаты по определению возможны.
- Требование «никогда не повторяются» означает:
  - либо отказаться от копий эмоций (сделать `EMOTION_COPIES = 1`) и ограничить количество игроков/карт,
  - либо ввести механизм «уникальность в рамках раунда»: при раздаче в руки и при сабмите гарантировать, что на стол не попадёт эмоция, которая уже у другого игрока.

### G) Новые блоки (игроки/очки, отчёт раунда, визуальная колода)
**Где:** `EmotionalRoomScreen.jsx` + новые компоненты в `client/src/components/emotional/`.
- Игроки/очки: можно использовать `gameState.players` + `gameState.scores`.
- Отчёт раунда:
  - данные частично есть в `gameState.roundResult` (`leaderSecretEmotion`, `votesCount`, `winners`).
  - не хватает маппинга `emotion -> список голосовавших никнеймов`, потому что `votes` на сервере хранится как `voterId -> slotId`, а наружу отдаётся только `votesCountBySlotId`.
  - понадобится расширить публичное состояние или отправлять отдельный `roundReport`.
- Колода: визуально можно рисовать по `room.emotionDeck.length` (нужно добавить публично в state, например `deckCount`).

## Оценка реализуемости и рисков (вероятность)
- Пункты, которые почти наверняка делаются быстро (90–100%):
  - убрать/заменить тексты (п.4, п.14),
  - спрятать руку вне submit (п.2),
  - сделать таймер круглым в нужный момент (через `RadialCountdown variant="full"`) (п.1 часть),
  - более плавные анимации/transition в существующих motion-компонентах (часть п.9, п.12),
  - «выложенная карта исчезает из руки» — уже сделано на сервере в `advanceToVote()` (п.12), нужно только убедиться что UI это не ломает.

- Средняя сложность (70–85% без неожиданностей):
  - убрать ощущение "обновления страницы" (это по сути переразметка фаз и уменьшение mount/unmount) (п.1),
  - перенос кнопки `Следующий раунд` в центр стола и синхронная очистка стола с задержкой 5 секунд (п.5),
  - новые desktop/mobile блоки и их адаптив/аккордеоны (п.8),
  - фикс перекрытия текста карточек (п.6) — потребует подбора формулы spacing/gap + CSS word-wrap.

- Высокий риск/нужны уточнения (40–70%):
  - абсолютная уникальность эмоций «никогда не повторяются у разных игроков» при текущей идее с `EMOTION_COPIES` (п.11.1).
    - здесь важно уточнить: уникальность нужна **в рамках одного раунда/стола** или вообще во всей игре?
    - при большом числе игроков и фиксированном словаре эмоций может не хватить уникальных значений.
  - мобильный drag вверх для постановки карты (п.9 mobile): технически реализуемо через `framer-motion drag`, но потребует аккуратной обработки скролла страницы/жестов и порога.

- Требования, зависящие от расширения server state (60–80%):
  - отчёт раунда с перечислением никнеймов, кто голосовал за эмоцию X (п.8.1/8.2) — сейчас сервер не отдаёт голосования поимённо.
